## 这个 lab 解决什么问题

lab8 结束时编译器已经能把源码变成机器码，但那是一份"直译"的机器码：
`2 + 3 * 4` 老老实实装进寄存器算三步。本 lab 在 gen 与后端之间插入一个
**优化器**，让同一份 IR 变短、变快，而程序的可观察行为一字不变：

```
前端(lab1~5)                中端(本lab)              后端
四元式 IR ──────────────→【opt：折叠/传播/CSE/死代码/窥孔】─→ x86-64 / vm / irvm / eval
                              ↑ -O 开关控制；不带 -O 行为与 lab8 完全一致
```

验收方式就是这条铁律的对拍版：**七套测试程序带 -O 走完原生管线，输出
必须与 lab3~lab8 沿用下来的期望文件逐字节一致**——优化器无权改变任何
一行 print。主演示只需两条命令：

```bash
./minicc9.exe    -ir tests/cases/opt.mc > before.txt
./minicc9.exe -O -ir tests/cases/opt.mc > after.txt
diff before.txt after.txt        # 每一类优化都肉眼可见
```

`after.txt` 的样子（对照 `before.txt` 的 40 余条四元式）：

```
main():
  g = 10
  print 14            ← 2+3*4 折叠成一个立即数
  x = 10
  print 30            ← x*2+x：传播后折叠
  print 1
  param 3
  param 4
  t10 = call cse, 2
  ...
cse(a@1, b@1):
  t2 = a@1 * b@1
  s = t2
  t3 = t2             ← CSE：第二个 a*b 复用第一个的结果
  t4 = s + t3
  return t4
```

## 与 lab8 的第一手对照

| | lab8 直译 | lab9 加 -O 后 |
|---|---|---|
| `print 2+3*4` | 三条运算 + 一条 print | `print 14` |
| `x=10; print x*2+x` | 装载/存储照单全收 | 操作数全部换成常量再折叠 |
| 函数里两次 `a*b` | 各算各的 | 第二次改写为复用第一次的结果 |
| `1 + 1;`（裸表达式） | 认真算一遍并丢弃 | 连同其临时一起删除 |
| goto 到紧邻标号 | 照发 | 窥孔删除 |

## 理论精要

### 1. 基本块：一切分析的舞台（8.4 节）

leader 规则三句话：段首是入口；跳转目标是入口；跳转的下一条是入口。
相邻入口之间就是一个**基本块**——顺序执行、无分支进出。本 lab 的局部
优化只在块内做：块内"上一次算过 a+b"才有确定答案，这正是后面一切
值追踪的前提。

### 2. 局部优化：一张常量表加一张可用表达式表（9.1 节）

逐条扫过基本块，维护两张表：
- **已知常量表**（名字 → 立即数文本）：操作数查表即得"常量传播"，
  双操作数全常量则直接算出结果——"常量折叠"。浮点用同一套 C double
  运算，位级一致、%g 打印不变；
- **可用表达式表**（(op,y,z) → 已有结果名）：相同键的第二次出现改写为
  对已有结果的拷贝——"公共子表达式消除"。

失效规则是正确性的全部：名字被重定义，以它为操作数的缓存条目全部作废；
CALL 清空一切（被调方可能改任何全局）；数组元素写入清掉该数组的全部
读取缓存——两个不同的下标表达式可能运行期同值，精确追踪不值得。

### 3. 数据流分析入门：活跃变量与不动点（9.2 节）

死代码删除问的是："这个赋值的结果今后还会被读到吗？"答案不在单个块里
（循环回边会把后面对变量的使用带回来），于是有了第 9 章的标准动作——
在 CFG 上解方程组：

```
use[b] = 块内先读后写的临时      def[b] = 块内写过的临时
out[b] = ∪ in[后继]              in[b]  = use[b] ∪ (out[b] − def[b])
```

从初值出发反复迭代直到两轮之间集合不再变化——**不动点**一定存在且是
最小解。实现只有几十行（见 opt.c 的 Pass C），却完整示范了"沿 CFG 传
播信息、迭代到自洽"的数据流范式：到达定值、可用表达式、非常活跃……
全是同一方程换个方向换个集合运算。

### 4. 保守性清单：优化器无权消灭错误

- 整数除/模的零除数**不折叠**：`print 1 / 0;` 必须保留运行时带行号报错；
- CALL 清空全部缓存：宁可少优化，不可错优化；
- 死代码只删 temps 名册里的系统临时（单一定义、无别名）；用户变量的
  死赋值不删——它可能藏着一次除零崩溃。

## 练习

1. **拷贝传播**：`b = a; c = b + 1;` 里把对 b 的使用换成 a——需要区分
   "拷贝关系表"与"常量表"的失效时机。
2. **DAG 式基本块优化**（8.5 节）：把整块构造成 DAG 再重生成四元式，
   对比与本 lab 逐条扫描的效果差异。
3. **跨块常量传播**：把 KNOWN 表升级成数据流方程（out = ∩ in 的 must
   分析），体会 must 与 may 分析方向和交并集的选择。
4. **强度削减**：`x * 2` → `x + x`、`x / 4`（无符号）→ `x >> 2`——
   在哪一步做才安全？
5. **优化统计可视化**：给每个 pass 加开关（-O1/-O2 风格），用
   tests/cases/func.mc 测出各 pass 单独与组合的原生运行耗时。

## 龙书 vs 现代

- **SSA 是数据流分析的终极形态**：每个名字只定义一次后，"到达定值"
  变成免费的——lab6 里"s 反复重写"的痛点在此得到根治；mem2reg 正是
  从本 lab 这类 IR 迈向 SSA 的那道桥。
- **Pass Manager**：现代编译器的优化是几百个 pass 的流水线，顺序本身
  就是调参对象（LLVM 的 pipeline 描述文件）。本 lab 的外层不动点循环
  是它的一粒种子。
- **成本模型**：教科书优化"必然更快"，工业界要问 profile-guided 的
  分支概率、cache 行为。`rep stosq` 清零未必快于展开循环——测量优先。
- **正确性验证的工业化**：本 lab 用七套程序 × 四引擎 × 期望文件对拍；
  工业界用差分测试、等价类检查与形式化验证（CompCert 证明了整只
  编译器）——思路同源，规模不同。
