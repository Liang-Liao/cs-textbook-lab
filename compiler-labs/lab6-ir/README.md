## 这个 lab 解决什么问题

lab5 产出了 AST——但树是"给人看的"形状：节点大小不一、孩子数量不定、
控制流藏在递归结构里。要在上面做**代码生成**，先要把它拍平成
"一条指令最多干一件事"的线性序列——这就是**三地址码**。本 lab 之后，
编译器有了清晰的"腰"：

```
前端(lab1~5)                    后端(lab7~)
源码 → token → AST+类型检查  →  四元式 IR  →  栈式VM / x86-64
                                  ↑ 本 lab
```

MiniC 同步升级到 v6：**函数定义/调用/递归/return、`&& || !` 短路布尔、
一维数组 `int a[8]`（6.4 节数组翻译）**。
执行方式也换了引擎：默认**编译到四元式再由 IR 解释器执行**；
lab5 的树遍解释器保留为 `-eval`——同一程序两引擎跑，输出必须逐字节一致
（对拍不是摆设：IR 引擎的三个真 bug 全是它抓出来的，见下文）。

## 理论精要

### 1. 三地址码与四元式（6.2 节）

每条指令至多两个操作数、一个结果。"四元式"= (op, arg1, arg2, result)，
本 lab 的 `Quad` 结构就是它（`src/ir.h`）。要点不是格式而是**抽象层级**：
- 比机器码高：无限个临时变量 `t1 t2...`、无限远跳转、不关心寄存器；
- 比 AST 低：控制流显式化（goto/标号）、求值顺序完全定死、类型已消解。

龙书说编译器分多趟的动机在此：**优化和代码生成都只面对这一层**，
换目标机只换后端。三地址码的常见物理形态：四元式（本 lab）、三元式、
间接三元式——四元式最直观，成了教学与早期编译器的事实标准。

### 2. 表达式翻译与"地址"（6.3/6.4 节）

`gen_expr` 返回一个**地址**——变量名、临时名或立即数文本。
这来自龙书"名字、临时、常量统一抽象为地址"的思想：
翻译 `a + b * c` 时不必关心操作数从哪来，拿到地址发一条
`t = a + b` 就完事。lab5 的"i2f 节点"在此落成 `t = (float)x`。

### 3. 回填：两遍解决"跳往何处"（6.6 节，本 lab 主秀）

翻译 `a && b` 时，`a` 为真的跳转目标（= `b` 的代码开头）在**发这条跳转时
还不知道**——`b` 还没生成。龙书给两个方案：先留空再回头填（回填），
或把整棵树生成完再扫一遍（分离的标号分配）。回填一遍完成，实现只是
四个小函数（`src/gen.c` 第 2 节）：

```
makelist(i)      单条悬空跳转 i 成链
merge(l1, l2)    两链拼接
backpatch(l, L)  目标标号 L 确定了，把链上所有跳转的目标填成 L
nextquad         下一条四元式的编号（= 悬空跳转的下标）
```

**布尔的两套翻译**是回填的主场：
- **跳转上下文**（if/while 条件）：`gen_cond` 返回 (truelist, falselist)，
  真假各一条悬空链——`B1 && B2` 的 SDD 是"backpatch(B1.t, B2 开头)，
  整体 falselist = 两条假链 merge"；
- **值上下文**（`print a && b`）：跳转代码定值到临时——真出口填到
  `t=1`，假出口填到 `t=0`，菱形汇合（6.6.5）。

同一个 `&&` 在两种位置生成**不同形状**的代码但语义一致——这是
"翻译由上下文（继承属性）决定"的最佳例子。break/continue 也走回填：
循环体内 break 发悬空 goto 挂进 breaks 链，出口标号确定后统一回填
（与 lab5 的 loop_depth 继承属性一脉相承，只是收集的东西从
"合法性"变成了"跳转链"）。

> **一个真实的坑**（双引擎对拍抓出的第三个 bug）：数值真值若只发
> "假跳转、真落空"，`&&` 碰巧正确（真落空恰好是右操作数开头），
> `||` 却是错的——左操作数为真时该**跳过**右操作数，落空却直接掉进
> 右边代码，`1 || 1/0` 就把除法执行了。教训：跳转代码的每个出口都
> 必须显式。代价是出现"goto 到紧邻标号"的冗余跳转——窥孔优化的
> 经典素材（练习 2）。

### 4. 过程调用（6.7 节）

```
param x        （每个实参一条，求值全部完成后才 call）
param y
t = call f, 2
```

调用序列的要点：**实参求值在调用之前完成**（gen 先遍历实参链再发
param/call）；VM 端 param 压栈、call 弹出 argc 个按位绑定形参。
函数体自己的 return 落空（比如 `if` 分支里 return 而尾部没有）由
gen 在函数末尾补隐式 `return` 兜底——返回类型对应的零值。
类型检查：实参按赋值规则逐个匹配（float 形参收 int 实参自动 i2f，
反向禁止）；void 调用只允许出现在表达式语句位置。

### 5. 数组：取址四元式与静态描述符（6.4 节）

龙书 6.4 的核心公式是"数组元素地址 = 基址 + 下标 × 宽度"。本 lab 把它
拆成两层：

- **IR 层只表达动作**：`x = a[i]` 发一条 Q_LDX、`a[i] = e` 发一条
  Q_STX，IR 里既没有乘法也没有指针。"基址在哪、元素多宽"是存储布局
  问题，留给执行后端——irvm 按 Val 格寻址，lab7 的栈帧按槽位，
  lab8 的 x86-64 直接吃进变址寻址 `[rbp+off+i*8]`；
- **静态描述符补足信息**：每个数组在 `IrProgram.arrays[]` 记下长度、
  元素类型、全局还是局部；每个 IR 名的静态类型也顺手登记进
  `types[]` 表。名字全局唯一让两张平表可行——这是"名字唯一化"机制
  的第二次回报。

语言边界（都是为了让类型系统保持干净的设计决定）：长度必须是编译期
常量；声明即零初始化（三个执行器共同的不变量："新空间必为零值"）；
数组**不作函数参数/返回值**——没有 C 式指针退化，也就没有悬空生命
周期问题；运行时不查越界，与 C 一致。递归时局部数组随激活各开一份，
`tests/cases/arr.mc` 的 probe 函数用这个性质自检。

### 6. 双引擎对拍：这一 lab 的工程方法

`eval.c`（树遍）与 `irvm.c`（IR 执行）实现同一语义。测试让 5 个程序
在两种引擎下跑并 diff 输出。这不是冗余——开发中它抓住了三个真 bug：
比较运算走错执行路径、全局变量副作用丢失（主段用了私有帧）、短路
失效（上面那个坑）。工业界的同款做法：解释器先定义语义、编译路径
与它对拍（CPython 的字节码 vs 解释器、V8 的各层优化互检）。

## 练习

1. **常量折叠**：`gen_expr` 对 `(int字面量 op int字面量)` 直接算出结果
   （`t2 = -5` 这种应消失）。这是 lab9 优化的第一课，在 IR 上做比在
   AST 上做更自然——你已经在"离机器更近"的层次上了。
2. **窥孔优化**：删除"goto 到紧邻标号"的冗余跳转（本 lab 生成器为
   语义正确保留了它们）。一个小遍历 + 标号重定向，效果立竿见影——
   `-ir` 前后对比。
3. **未引用标号消除**：窥孔删掉跳转后，某些 Q_LABEL 再无人引用，
   一并清掉（无用代码删除的最小版）。
4. **函数原型（两遍扫描）**：现在函数必须先定义后调用。第一遍只收集
   全部签名（顶层扫到 func_like 就登记签名、跳过函数体），第二遍
   正常翻译——`main` 调 `f` 而 `f` 定义在后面的程序就合法了。
5. **if_false 的对偶**：把数值真值改成 `if_true x goto T` + 假落空的
   形态，观察哪些地方多余跳转变少、哪些变多——体会"出口显式"与
   "落空利用"之间的权衡。
6. **数组边界练习**：数组已经落地（Q_LDX/Q_STX + 描述符表）。试着给它加
   运行时越界检查（LDX/STX 前比一下下标与描述符里的长度），再想想为什么
   真实编译器把它做成可选（每次访问的两次比较 vs 安全网）；然后支持
   "数组作函数参数"——你会发现自己不得不先发明引用或指针，这正是 C 把
   数组退化成指针的原因，也是 lab7+ 的入口问题。

## 龙书 vs 现代

- **LLVM IR 与教科书四元式的距离**：龙书的三地址码是无限临时、随意
  重赋值；LLVM IR 是 **SSA**（每个名字只定义一次，φ 显式汇合）——
  那正是本 lab `t5 = s + i; s = t5` 里"s 被反复重写"的痛点的解法。
  LLVM 的 `alloca/load/store` 又故意退回非 SSA 处理可变变量——
  理解四元式才能理解 SSA 解决了什么。
- **真实编译器不止一层 IR**：GCC 从 GENERIC 到 GIMPLE 到 RTL；
  rustc AST→HIR→MIR→LLVM IR；V8 Ignition 字节码之上还有 TurboFan
  的 Sea of Nodes。龙书第 6 章"一层中间表示"是教学简化，但"每层
  只服务一类变换"的思想被完整继承。
- **回填思想的延续**：现代两阶段指令选择（先选指令、后寄存器分配）
  里"先发占位、后定细节"无处不在——分支偏移在汇编器 relaxation、
  linker 的重定位（relocation）里回填的是地址而不是标号。你每次
  `gcc -c` 生成 .o 再链接，都在跑一遍放大版的 backpatch。
- **param/call vs 真实调用约定**：龙书的 param 四元式假设无限参数栈；
  x86-64 前 6 个整型参数走寄存器、System V 的调用约定是两套并存的
  世界。lab7 的活动记录会把"参数在哪"从 VM 的链表变成真实的栈布局。
- **短路的语义地位**：C 系语言把短路写进标准（`&&`/`||` 求值顺序
  有定义）；Java 同；Rust 更进一步用它做控制流（`&&` 就是 `and`，
  配合 `?`/`match`）。而 Pascal 的 `and`/`or` **不**短路（两个操作数
  恒求值）——同一个运算符，两种语言设计，翻译时一个要回填一个不要。
