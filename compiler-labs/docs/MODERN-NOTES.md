# 龙书 vs 现代编译器：逐章"过时内容"指正与演进

龙书第 2 版（2006 年英文版）仍是编译原理最系统的入门教材，它的**理论主干至今没有过时**
（正则/自动机、上下文无关文法、LL/LR 分析、属性翻译、数据流分析）。
但书中不少"工程实践"部分反映的是 1970s~2005 年的工具生态，与今天的工业界有明显代差。
学习时按本文对照修正认知即可——**理论照学，工程观点按现代更新**。

> 各 lab 的 README 末尾也有针对该章的"龙书 vs 现代"小节，这里是全局汇总。
> **进度**：第 2~12 章的配套实验（lab0~lab12）已全部实现。

## 第 2 章：一个简单的语法制导翻译器

| 龙书内容 | 现状 |
|---|---|
| 输入缓冲区对（两个半区轮流装入，图 2 附近的 `*EOF*` 哨兵技术） | **已淘汰的工程细节**。那是磁带/慢速 I/O 年代为省内存设计的技术。现代编译器把整个源文件一次性读进内存（或 mmap），维护一个指针即可。我们 lab 的实现就是"整文件 + 游标"。 |
| 后缀表达式、三地址码作为示例 IR | 概念仍然必学；后缀式活在 JVM/.NET 字节码、PostScript、RPN 计算器里。但现代编译器主流 IR 是 **SSA 形式**（见第 6 章条目）。 |
| 语法制导翻译方案（嵌入式语义动作） | 理论框架仍重要；工程上的化身是"递归下降函数里随手写副作用/返回值"（lab3 就是这么做的）。 |

## 第 3 章：词法分析

| 龙书内容 | 现状 |
|---|---|
| 用 Lex/flex 从正则描述自动生成词法分析器 | flex 今天仍存在且可用，但 **GCC、Clang、V8、TypeScript、Go 等主流编译器全部手写词法分析器**（lab1 的做法）。原因：更好的错误信息（token 带精确源码区间）、无生成步骤、可微调性能、方便处理上下文（如 C++ 的 raw string、C 的行拼接）。**"正则 → 自动机"的理论一点没浪费**——它是你理解 token 定义、写出正确手写 lexer 的根基（lab2 把整条理论链跑通，并做一个 mini-flex）。 |
| 关键字识别：先按标识符匹配，再查保留字表 | 依然完全正确，工业界就是这么做的（表可能是 trie / 完美哈希 / `switch` 优化成跳转表）。 |
| DFA 最小化（Hopcroft 算法，3.9 节） | 理论必学；工程上 flex **并不最小化** DFA——状态数多一点无所谓，换取构造快、表紧凑（用字符等价类压缩转移表）。 |
| 正则引擎 | 补充一个龙书基本没讲的生态事实：正则引擎分两派——**回溯派**（PCRE、Python `re`、Java `java.util.regex`，实现简单但最坏指数级，有 ReDoS 灾难回溯问题）与**自动机派**（RE2、Rust `regex`，基于 NFA/DFA 模拟，线性时间但不支持反向引用）。lab2 实现的是自动机派。 |
| 源码字符集假定 ASCII | 现代语言多为 UTF-8，标识符允许 Unicode（Rust/Go/Java 一直支持，C23 才标准化 UCN 标识符）。我们的 lab 简化为单字节 ASCII，注意这是简化而非标准。 |

## 第 4 章：语法分析

| 龙书内容 | 现状 |
|---|---|
| LALR(1) 是 parser generator 的主流，yacc/bison 大量使用 | **这是全书"过时感"最强的一章**。LALR 生成器（yacc, 1970s~）确实统治了 30 年，但 **GCC 2004 年起弃用 yacc 改为手写递归下降**；Clang、rustc、TypeScript、Go、V8 等现代编译器清一色手写**递归下降 + 运算符优先级爬升（precedence climbing，又称 Pratt parser）**。原因：错误恢复与诊断质量（Clang 的报错体验是卖点）、支持 IDE 的增量解析、代码可控性。bison 今天仍在维护并被 GNU 工具链内部使用，但新项目占比很低。 |
| 消除左递归（4.3 节）后用 LL(1) 处理表达式文法 | 理论必考，但注意：**消除左递归会破坏运算符的左结合性**，需要额外的语义补救。工程上手写 parser 直接用循环写 `E → T {(+|-) T}`（龙书 4.3 节也给了这个等价形式），左结合天然正确。lab3 会专门演示这个坑。 |
| LL(1)/LL(k) | 纯 LL(1) 生成器（如 JavaCC）萎缩。但 **ANTLR 4 用 ALL(\*)（自适应 LL）重新点燃了 LL 系**——运行时根据需要向前看任意多符，实践中很好用。PEG（解析表达文法）+ packrat 是另一个现代 LL 流派（Go 早期用过，解析组合子库常用）。 |
| GLR | 龙书未重点讲。GLR（广义 LR，并行走所有候选分析）是处理**真二义文法**的利器：C++ 的声明/表达式歧义、自然语言。现代代表：**tree-sitter**（用增量 GLR 给编辑器做语法高亮，GitHub/VS Code/Neovim 都在用）、Elkhound。 |
| 悬空 else 的移进/归约冲突 | 永恒经典。yacc 的处理（默认移进）仍是标准做法；手写递归下降里这个问题**根本不会出现**（你自然地把 else 绑给最近的 if）——这是 lab4 对拍时要体会的对比。 |
| lexer hack（typedef 名字影响词法，2.x/4.9 提及） | C/C++ 的 `a * b;` 到底是乘法还是声明，需要符号表反馈给词法/语法。Clang 的做法：先无歧义解析，再延迟消歧。了解即可。 |

## 第 5 章：语法制导翻译

| 龙书内容 | 现状 |
|---|---|
| SDD（语法制导定义）、综合/继承属性、依赖图、L 属性 | **作为形式系统的属性文法基本只活在教学里**，工程界很少显式构造依赖图。但它的思想无处不在：手写递归下降里，**函数返回值 = 综合属性，函数参数 = 继承属性**，L 属性限制恰好对应"一遍自左向右深度优先求值"——这正是所有真实编译器前端的形状。lab5 就是这个形态。 |
| 属性文法系统（如 FNC-2 等工具） | 已消失。 |

## 第 6 章：中间代码生成

| 龙书内容 | 现状 |
|---|---|
| 三地址码、四元式、回填技术 | **教学核心不变**，lab6 照此实现。但注意一个大的代差： |
| （第 6 章整体以线性三地址码为 IR） | **现代主流 IR 是 SSA（静态单赋值）形式**：每个变量只赋值一次，φ 函数在控制流汇合处合并。GCC（GIMPLE）、LLVM IR、V8（Sea of Nodes）全部基于 SSA/SSA 变体。SSA 让优化（常量传播、公共子表达式、死代码删除）变得稀疏而高效。龙书 2 版只在 9.7 节简短介绍了 SSA，**这是本书相对工业实践最大的缺口**，强烈建议补充阅读：LLVM 的 Kaleidoscope 教程、《Engineering a Compiler》（Cooper & Torczon）。 |
| 类型检查、隐式/显式转换 | 概念仍然标准。现代趋势是依赖类型的类型系统（Rust 的 trait/生命周期、Haskell/Idris），远超龙书范围但同源。 |

## 第 7 章：运行时环境

| 龙书内容 | 现状 |
|---|---|
| 栈式活动记录（activation record）、控制链/访问链、参数传递 | **完全不过时**——C/C++/Java/Go 的函数调用今天仍是这样（lab7 实现）。细节差异：真实 ABI 用寄存器传前几个参数（System V 与 Win64 还不一致）；龙书的"参数全压栈"是教学简化。 |
| 堆管理与垃圾回收 | 龙书讲的是基础标记-清除。现代 GC 已经进化到分代、增量、并发（G1/ZGC/Shenandoah），远超本书；想深入读《The Garbage Collection Handbook》。 |
| 龙书基本未讲 | **闭包与逃逸分析**（把"逃不出去"的对象从堆挪到栈——性能利器）、**JIT 的栈上替换**、**协程的栈切换**（stackful 如 goroutine 有独立栈 / stackless 如 JS async 只存续体）、**尾调用优化**。 |

## 第 8 章：代码生成

| 龙书内容 | 现状 |
|---|---|
| 指令选择（树重写/tile 匹配） | 思想延续：LLVM 用 TableGen 描述模式做 SelectionDAG/GlobalISel 匹配；iburg 一脉仍用于嵌入式后端。 |
| 寄存器分配：图着色（Chaitin） | 图着色是经典必学，但工程已多元：**linear scan**（JIT 要快，V8/C1 用）、**LLVM greedy**（优先级驱动的增量着色）、PBQP。现代还做分配与调度的联合优化。 |
| 指令调度（VLIW/EPIC 背景浓厚） | 龙书 2 版出版时正是 Itanium（EPIC/VLIW）如日中天——**Itanium 2004 年后商业失败退场**，桌面 CPU 走了动态乱序执行路线，静态指令调度的收益下降（但超标量 CPU 的软件调度、DSP/GPU 上的静态打包仍然重要）。 |
| 直接生成机器码（寄存器分配 + 指令选择 + 指令调度） | **今天几乎没人手写完整后端**：工业界把目标码生成外包给 LLVM/GCC 后端，自己只生成 LLVM IR。**WebAssembly 成为新的"通用虚拟目标"**。lab8 仍会手写一个极简 x86-64 后端（教学价值无可替代），但请记住这是"看透黑箱"的练习，不是工程推荐。 |

## 第 9 章：机器无关优化

| 龙书内容 | 现状 |
|---|---|
| 位向量数据流框架：到达定值、可用表达式、活跃变量 | **基础必学**，lab9 实现常量折叠/传播、死代码删除等入门优化。但要更新认知： |
| （数据流分析在非 SSA 的线性 IR 上做，迭代到不动点） | **现代编译器全在 SSA 上做稀疏分析**：φ 函数 + 支配树让"到达定值""活跃变量"退化为简单的 def-use 链遍历，速度快、精度高（稀疏条件常量传播 SCCP 是代表）。GCC 4.0（2005）全面转 SSA。 |
| 龙书基本未讲（2006 年前太新/太小众） | **过程间优化与 LTO**（链接时优化）、**PGO**（剖析制导优化）、**投机优化与去优化**（JIT 假设"这个分支大概率不走"并保留逃生门——V8/HotSpot 的核心武器）、**内联缓存**、**自动向量化**（superword、polyhedral 模型）、**即时编译分层**（解释器 → 基线 JIT → 优化 JIT，如 V8 的 Ignition/Sparkplug/Maglev/TurboFan）。 |
| 编译器正确性 | 现代方向：优化的形式化验证（Alive2 验证 LLVM 优化保持语义、CompCert 验证的 C 编译器）。 |

## 第 10 章：指令级并行

| 龙书内容 | 现状 |
|---|---|
| 数据依赖（真/反/输出相关）与控制依赖 | **永恒的基石**。今天仍是调度、向量化、并行化正确性的第一性判据；变的只是表示法——现代编译器在 SSA/PDG（程序依赖图）上计算依赖，龙书用 def-use 链。 |
| 基本块 list scheduling（DAG 拓扑排序塞进有限寄存器与延迟模型） | 思想必学，但认清前提：调度的收益来自"值驻留寄存器 + 流水线空泡"。若后端像我们 lab8 那样所有值都过内存，先做调度等于无米之炊——**寄存器分配在前，调度才有的放矢**（工业后端因此把指令选择→调度→分配的顺序反复组合实验）。 |
| VLIW / EPIC / 软件流水线 | 龙书成书时正是 Itanium（EPIC/VLIW）如日中天——**Itanium 2004 年后退场**，是体系结构史上最大的豪赌失败之一。静态打包指令的遗产活在 DSP/GPU 与 JIT 的循环流水里；通用桌面市场由硬件乱序执行接管，编译器的职责收缩为展开、消除分支、为向量化铺垫。 |
| 循环展开 | **至今有效且常用**（-O2/-O3 都做），目的已从"填满流水线"演变为"减少循环开销、扩大基本块、给后续优化更大窗口"。代价是指令缓存膨胀——现代编译器按成本模型决定展开系数，而非拍脑袋 ×4。 |
| 本章整体的工程地位 | 通用 CPU 上大部分 ILP 已由硬件乱序执行"免费"提供；编译器的 ILP 主战场转移到了**自动向量化**（LLVM loop-vectorize/SLP）与 GPU/DSP 的静态打包——理论基础与本章的依赖分析同源。 |

### 配套实验设计（已实现）：lab10-loop「循环分析与优化」

> 承接第 9 章"数据流分析入门"留下的循环分析（自然循环），并为第 10 章的
> ILP 叙事提供可测量的载体。**已落地为 [lab10-loop](../lab10-loop/)**；实现相对本节
> 的三处有意收紧（展开条件取"N 为正偶数"规范形态、以结构性守卫替代本节预想的
> lab11 依赖检查安全网、for 体 continue 暂不支持留作练习）以
> [lab10-loop/README.md](../lab10-loop/README.md) 的说明为准。

- **语言扩展**：`for (init; cond; step) stmt`。lexer 新增 T_KW_FOR；parser 把
  for **直接拼装成既有 AST 组合**（等价于 `{ init; while (cond) { body; step; } }`）
  ——gen 与四个执行引擎零改动，旧测试期望零变化。
- **pass 蓝图**（挂入 lab9 的 -O 不动点框架）：
  1. 支配关系迭代计算（dom[n] = {n} ∪ ∩ dom[pred]，沿 CFG 前向传播）；
  2. 回边 n→h（h 支配 n）识别 → 自然循环提取（从 n 向后收集、遇 h 止）；
  3. preheader 构造：插入前置块，并把所有指向循环头的边改写到 preheader；
  4. LICM 不变量外提：纯运算四元式 + 操作数在循环内无重定义 + 结果临时仅
     循环内使用（出口支配检查取保守版）→ 移入 preheader；
  5. 计数循环展开 ×2：识别"头条件 `i < N` + 步进 `i = i + 1`"规范形态，
     界为编译期常量且可整除时执行（余数循环留作练习）；展开前跑 lab11 的
     依赖检查作为安全网。
- **CLI/观测**：统计行扩展"外提 x、展开 y"；新增 `-cfg` 开关 dump 基本块 +
  支配关系 + 循环清单；`tests/bench.sh` 计时软验证（不计入硬性通过标准）。
- **测试计划**：lics.mc / unroll.mc 各冻结 `-ir` 与 `-O -ir` 双 dump 对拍；
  全量旧用例带 -O 逐字节一致的验收照旧。

## 第 11 章：面向并行与局部性的优化

| 龙书内容 | 现状 |
|---|---|
| 迭代空间、仿射数组下标、依赖距离/方向向量 | **Polyhedral 编译模型的正统源头**，至今活跃：LLVM Polly、MLIR affine dialect、Pluto。理论没有过时，过时的是"自动并行化会普及"的预期——工业界至今保守，重仓使用者集中在高性能计算库（BLAS/LAPACK）。 |
| 数据依赖分析（GCD 测试、Banerjee 不等式） | 一维/仿射情形仍是教科书标准；工程上精确依赖分析是 NP-hard，实用系统大量依赖保守回退（"拿不准就不变换"）。教学上做一维 + 常量步长的最小版，恰好落在"够用且可证明"的区间。 |
| 复用与局部性（cache line、时间/空间局部性） | **比 2006 年更重要**：内存墙越垒越高，CPU 主频停滞而核数/缓存层级持续膨胀。分块（tiling）思想原样迁移到 GPU shared memory 与分布式切分。 |
| 自动并行化 | 至今仍是"研究成功、产品保守"：全自动并行只在小众领域落地，**OpenMP 手工标注是工业主流**。教学顺序因此是先学"判定变换合法"，再谈"交给谁去并行"。 |

  3. 合法性驱动的变换：lab10 的展开升级为"依赖检查通过才展开"（两章呼应）；
     完美嵌套 + distance≠0 时启用循环交换；
  4. `-space` 迭代空间 ASCII 可视化（网格 + 依赖箭头）；
  5. bench.sh 缓存计时实验：stride-1 vs stride-k、朴素 vs 分块遍历（软验证）。
- **测试计划**：mat.mc（二维初始化/转置/小规模乘法）、dep.mc（依赖正反例，
  stderr 对拍）、全量旧用例回归零变化。

## 第 12 章：过程间分析

| 龙书内容 | 现状 |
|---|---|
| 调用图、内联 | 内联是**现代编译器单笔收益最大的优化**（LLVM 的 always-inliner + 成本模型 inliner 是管线中权重最高的 pass 之一）。调用图在 OOP 语言里要先去虚化（devirtualization）才能精确；MiniC 无函数指针、函数先定义后用，天然得到静态精确图（教学优势点）。 |
| 过程间常量传播（IPCP） | 思想完整存活于 LLVM 的 IPSCCP（过程间稀疏条件常量传播）。must 交集 + 调用图不动点的框架与龙书一致，实现细节换成 SSA 后更简单。 |
| mod/ref（可能写/必读信息） | 今天以别名分析（alias analysis）与 MemorySSA 的形态存在，是 CSE、LICM、DCE 敢不敢下手的关键依据——正是 lab9 里"CALL 清空全部缓存"这条保守规则的科学替代品。 |
| 龙书的隐含假设 | 所有过程间分析默认**闭世界**（全部代码可见）；工程上要面对动态链接、JIT 动态加载、跨语言 FFI——**LTO（链接时优化）**是工业界的折中答案。 |

## 龙书整体没有覆盖、但今天很重要的主题

1. **编译器 ≠ 单遍批处理**：增量编译（rustc、IDE）、语言服务器（LSP）、语法高亮容错解析（tree-sitter）已经成为语言工具链的标配需求。
2. **编译速度是一等公民**：Go 的设计目标、tsc 的切肤之痛、rustc 的增量编译都是围绕"开发者等待时间"的工程。
3. **LLVM/GCC 双寡头生态**：新语言（Rust/Swift/Julia）几乎都从"生成 LLVM IR"起步，自举完整后端是极少数派（Go、V8、Wasm 工具链）。
4. **安全与混淆**：反编译、混淆、可信编译链（Reproducible Builds、SLSA）是工程新话题。
