> 对照龙书第 3 章（3.1 词法分析器的作用、3.3 词法单元的规约、3.4 记号的识别）
> 源码：[`src/token.h`](src/token.h) · [`src/lexer.c`](src/lexer.c) · [`src/symtab.c`](src/symtab.c) · [`src/main.c`](src/main.c)

## 这个 lab 解决什么问题

把 MiniC 源文件的**字符流**切成**记号流**：

```
输入:  int radius = 10;
输出:  4:1   T_KW_INT    int
       4:5   T_IDENT     radius
       4:12  T_ASSIGN    =
       4:14  T_INT_LIT   10
       4:16  T_SEMI      ;
```

为什么需要这一步？因为 `>` `=` 两个字符在语法上是一个不可分割的整体（`>=`），
而 `"radius"` 十六个字符才是一个整体。**语法分析器处理"记号"这个粒度**，
把分词的脏活（空白、注释、最长匹配、错误字符）全部隔离在词法层。

## 理论精要

### 1. 词法单元用正则式描述（3.3 节）

龙书用正则式精确刻画每类记号，MiniC v1 的定义：

```
标识符   [A-Za-z_][A-Za-z0-9_]*
整数     [0-9]+
浮点数   [0-9]+\.[0-9]* | \.[0-9]+
注释     //...换行  |  /* ... */
```

本 lab **手工**实现了这些正则式的识别（if/while/switch 写状态转移）；
lab2 将走正统路线：正则 → NFA → DFA → 让自动机自己识别。

### 2. 最长匹配与超前查看（3.4 节）

- **最长匹配**：`>=` 绝不能吐成 `>` `=`。做法：按"宽类别"一路吃到不能再吃。
  数字扫描的 `while (isdigit(...)) advance(...)` 就是最长匹配的化身。
- **超前查看**：读到 `=` 时必须偷看下一个字符：是 `=` 则合并成 `==`，
  否则 `=` 单独成记号。偷看了但不消费 = "回退"，本实现直接移动 pos 游标。
- 用 `demo.mc` 第 22 行的 `(area <= 500)` 验证：输出里只有一个 `T_LE`。

### 3. 关键字 vs 标识符（3.4 节）

`if` 完全匹配标识符的正则。标准解法（也是工业界做法）：**先按标识符扫描，
再查保留字表**（`keyword_lookup()`）。lex 的另一种写法是把关键字规则放在
标识符规则前面、靠优先级取胜——lab2 的 mini-flex 会用这种。

### 4. 符号表与字符串驻留（2.7 节）

词法阶段的符号表用法是**驻留**（intern）：`radius` 出现 8 次只在表里存一份，
之后所有记号的 `lexeme` 指向同一地址——**比较标识符从此只比指针**。
跑 `./minilex.exe -s demo.mc` 看看去重效果。lab5 会把它扩展成带类型、
带作用域链的完整符号表。

### 5. 词法错误恢复（3.1 节）

词法层的恢复非常朴素：**报错、跳过坏字符、继续**。对比 `errors.mc` 的输出：
5 个错误一次性全部报告（而不是见错就停）。错误记号 `T_ERROR` 保留在流里，
让上层阶段知道"这里少了个东西"。

> 一个真实世界的坑：中文输入法的**全角标点**（`；` `（）`）是本 lab
> 测试用例之一——这是初学者最常见的"看不见的"词法错误。

## 练习

1. **加十六进制字面量** `0x1F`（提示：在数字分支前先识别 `0x` 前缀）。
2. **加科学计数法** `1e-5`、`6.02e23`（`[0-9]+(\.[0-9]*)?([eE][+-]?[0-9]+)?`）。
3. **加 `++`/`--`**：注意 `a+++b` 按最长匹配应切成 `a ++ + b`，
   这在 C 语言里是合法且有歧义性的著名例子。
4. 把列号统计改成"真实显示列"（制表符算到下一个 8 的倍数）。
5. 故意把 `keyword_lookup` 的线性查找换成"先 intern 再比较"——
   性能会变好还是变差？为什么？（答案：变差，先驻留关键字表才是对的。）

## 龙书 vs 现代

- **输入缓冲区对（3.2 节）已淘汰**：那是磁盘/磁带时代为避免"每字符一次 I/O"
  设计的双半区缓冲 + 哨兵技术。现代机器内存充足，**整个文件一次读入**
  （`read_file()`），游标随便移动。3.2 节读懂思想即可，不必实现。
- **flex 没有死，但主流编译器都手写**：GCC、Clang、V8、TypeScript 的词法器
  都是手写的（和本 lab 同款思路）：错误信息可以带精确的源码区间、
  能处理 C++ raw string 这类上下文相关的词法、没有生成步骤。
  "正则→自动机"理论（lab2）仍是理解这一切的根基。
- **符号表**：驻留思想在现代编译器无处不在（LLVM 的 `StringMap`、
  V8 的 internalized string）；带作用域的完整符号表见 lab5。
- 龙书默认源码是 ASCII；现代语言源码是 UTF-8，标识符可含 Unicode
  （Rust/Go 一直支持，C23 才标准化）。本 lab 简化为单字节，列号按字节计。
