## 这个 lab 解决什么问题

前七个 lab 里，"执行"始终由我们自己写的解释器代劳——VM 是 C 程序，
MiniC 程序只是它的数据。本 lab 之后不再有中间人：**源码被翻译成真正的
x86-64 机器指令**，gcc 只负责汇编和链接：

```
前端(lab1~5)                  后端
源码 → token → AST+类型检查 → 四元式 IR ─┬→ x86-64 汇编(本lab) → .exe
                                        ├→ 栈式 VM(lab7, -vm)
                                        ├→ C 递归解释器(-irvm)
                                        └→ 树遍解释器(-eval)
                                              ↑ 一份 IR，四台"机器"对拍
```

MiniC 语言与 gen.c 的翻译逻辑不动。变化全部发生在最后一级：
- 每个 IR 名从"虚拟栈槽位"变成真实栈帧里 `[rbp-off]` 的 8 字节格；
- param/call 从数组搬运变成 Windows x64 调用约定（rcx/rdx/r8/r9 +
  xmm0-3 + 影子空间）；
- 返回值从累加器 acc 变成 rax / xmm0；
- `int g[5]` 变成 `.comm` 零初始化的全局数据，`a[i]` 变成一条变址寻址。

生成的 `fn_add` 反汇编（objdump 抽查）——逐四元式翻译的教科书形态：

```asm
fn_add:
        push   %rbp                    ; 旧帧指针入栈
        mov    %rsp,%rbp               ; 建新帧
        sub    $0x40,%rsp              ; 局部区+暂存区+出栈区，16 对齐
        mov    %rcx,-0x8(%rbp)         ; 形参 a 从寄存器搬进槽位
        mov    %rdx,-0x10(%rbp)        ; 形参 b 同上
        lea    -0x18(%rbp),%rdi
        mov    $0x1,%rcx
        xor    %eax,%eax
        rep stos %rax,(%rdi)           ; 其余局部清零（零初始化不变量）
        mov    -0x8(%rbp),%rax         ; t1 = a
        mov    -0x10(%rbp),%rcx        ;     + b
        add    %rcx,%rax
        mov    %rax,-0x18(%rbp)
        mov    -0x18(%rbp),%rax        ; return t1 → rax
        mov    %rsp,%rbp ... ret
```

## 理论精要

### 1. 逐四元式翻译：最朴素的 getReg（8.2 节）

龙书 8.2 的简单代码生成器问一个问题："这条四元式的操作数该在哪个寄存
器？"我们的答案最朴素——**谁都不在，全从内存装**：每条指令 load 操作数
到 rax/rcx（整数）或 xmm0/xmm1（浮点），运算一条，写回内存。代价是
冗余的访存（上面 fn_add 里结果刚写回又立刻读出），换来的是正确性显然、
每条 IR 与一小段机器码一一对应。"让值留在寄存器里别下来"就是寄存器
分配——练习 1 让你迈出第一步。

### 2. 栈帧与调用序列：第 7 章的机器兑现（8.2/7.2 节）

帧布局与调用序列在 vm.c 里你已见过一次，这里换成了硬件与 ABI 的版本：
- **Windows x64 约定**：前 4 个实参走 rcx/rdx/r8/r9（浮点走 xmm0-3，
  按位置对应而非统一排队）；第 5 个起压栈；调用者必须预留 32 字节
  **影子空间**；call 时 rsp 须 16 字节对齐——所以帧大小向上取整到 16；
- 实参求值后先进本帧的**暂存槽**再装寄存器：嵌套调用的外层实参会先
  入暂存、内层压在其上，因此暂存是一张栈（深度峰值在装载期算出）；
- 出栈区属于调用者自己的帧，call 返回后无需清理——固定帧让 7.2 的
  "caller 还是 callee 清栈"之争直接消失；
- 局部区序言里 `rep stosq` 清零：三个解释器的"新空间必为零值"不变量，
  在机器上对应这一条指令。

### 3. 寻址模式与数组：6.4 的最后一步

IR 里 Q_LDX/Q_STX 只表达"按下标读写"；基址在哪、宽度多少，一路从
描述符传到这里，最终变成一条变址访存：全局数组 `leaq G_a(%rip),%r10`
后 `movq (%r10,%rax,8)`，局部数组连 leaq 都省成 `[rbp+off+i*8]` 的形状。
"地址 = 基址 + i × 宽度"这个公式，从 6.4 的纸面到这里才算真正落地。

### 4. 为什么需要运行时库 rt.c

打印不直接调 printf——printf 是可变参数函数，Windows x64 要求可变参
调用把浮点实参同时放进通用寄存器并在 AL 里报数。包成固定签名的
`minic_print_int/minic_print_float`，生成代码面对的约定立刻回到朴素形
状。除零助手同理：idiv 前生成 `test/jnz` 绕行，为零则带着源行号进
`minic_div_zero`（不返回）。rt.c 里的 `main` 只做一件事——把控制权交给
编译出的 `mc_top` 段（名字避开用户可能定义的 main 函数）。这就是
libc/crt0 关系的微缩模型：**运行时的接口设计是编译器作者的自由度**，
接口越窄，后端越简单。

### 5. 已知限制（教学取舍，记录在案）

- **浮点 NaN 比较的无序语义**：浮点 jcc 对 NaN 的真值与解释器相反
  （jb/jbe 视 NaN 为真、je 当假；解释器 truthy(NaN)=真），且都不合
  IEEE"无序=假"。MiniC 不产生 NaN，分歧仅在不可达场景；标准做法是
  comisd 后加 jp 双分支，为教学清晰度暂不引入。（词法层接受 `1e999`
  一类字面量会得到 inf 而非 NaN——inf 经 gen 文本化后在 IRVM 侧会被
  当作名字读成 0，属另一条已知边角，构造测试时请避开。）
- **字面量池 / 全局表等固定容量**：超限时明确报错拒绝（fail-fast），
  不做动态扩容——容量上限本身就是本系列反复出现的工程主题。
- **整数的实际口径**：字面量钳在 INT32_MAX；但四个引擎的运算统一在
  64 位上进行（解释器用 long，原生侧用 addq/imulq 等 64 位指令），
  并**不**按 32 位回绕——溢出程序四引擎一致、可正常对拍，只是与
  "C int 32 位回绕"的直觉不同；严格 32 位语义留作练习。

## 练习

1. **寄存器分配第一步**：让只使用一次的临时直接在寄存器间传递
   （观察 fn_add 里"写回又读出"的对消）。做完拿 `gcc -O0 -S` 对比同款
   C 程序——你会看到一模一样的思路。
2. **窥孔优化**：删"store 后紧跟 load 同一位置"的对消对、goto 到紧邻
   标号的跳转。生成前后 diff 汇编，效果立竿见影。
3. **数组越界检查**：Q_LDX/Q_STX 前生成比较 + 跳进 minic_bounds_fail。
   测一测加上检查后 fib(20) 慢了多少——安全的价格从此有了数字。
4. **System V 移植**：把调用约定换成 Linux 版（rdi/rsi/rdx/rcx/r8/r9、
   无影子空间、返回 struct 用 rax:rdx），同一份 IR 在 WSL 里跑通——
   你会真切体会"目标机相关"四个字落在哪几行。
5. **尾调用优化**：`return f(...)` 编译成"替换自身栈帧后 jmp"。用无穷
   递归程序验证它真的不再溢出（对照测试 5b 的崩溃退出码）。

## 龙书 vs 现代

- **两阶段后端**：现代编译器把指令选择与寄存器分配拆成独立阶段
  （图着色、线性扫描……），本 lab 把它们捏在"逐四元式直译"里——
  这正是 1980 年代编译器的真实形态，也是理解后续优化的地基。
- **调用约定的战国**：SysV（Linux/macOS）、Win64、arm64 各一套；
  本 lab 只实现了 Win64。抽象层（IR）稳定而约定多变，恰是"中间表示"
  存在的意义。
- **没人手写代码生成了吗？** 工业编译器的后端来自模式匹配的指令
  选择器（LLVM TableGen、GCC MD），但 JIT（V8、PyPy）与教学编译器
  至今仍在用本 lab 这种"模板直译"——快、小、可控。
- **-O0 与 -O2 的距离** = 本 lab 与工业界的距离。所有值过内存的
  "笨代码"正是 -O0 的样子；优化章节（lab9 及第 9/10 章）的全部意义，
  就是在不改变语义的前提下抹掉这里的浪费。
