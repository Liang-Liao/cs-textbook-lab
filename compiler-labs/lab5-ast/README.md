## 这个 lab 解决什么问题

lab3 的递归下降"边分析边求值"——值是函数返回值，语句一结束就没了；
语言也只到 `print 表达式;`。要长成真正的编译器前端，两件事必须发生：

```
1. 翻译结果要能"留下来"  → 每个产生式构造 AST 节点（语法制导翻译）
2. 程序要能"被理解"      → 变量是谁？什么类型？在哪可见？（符号表 + 类型检查）
```

于是 MiniC 升级到 v4：**变量声明/初始化、赋值、while/break/continue、块级作用域、
int/float 双类型检查**。检查全部通过后，第二趟树遍解释执行——`print` 照样出结果，
而 lab3 的表达式测试集**原样第三跑**（输出逐字节一致）。

## 与 lab3 的第一手对照（同一个递归下降，翻译目标变了）

| | lab3 直接求值 | lab5 构造 AST |
|---|---|---|
| parse 函数返回值 | `Val`（一个数） | `AstNode*`（一棵子树） |
| parse 函数参数 | 无 | `loop_depth` 等（**继承属性**） |
| 趟数 | 一趟（分析=执行） | 两趟：分析+检查，再执行 |
| 变量/类型 | 无 | 符号表 + 类型检查 |

一句话：lab3 里"综合属性"只活了一瞬间（算完就丢）；lab5 把它**物化成树**，

## 理论精要

### 1. 语法制导定义：文法带上属性（5.1~5.2 节）

在每个文法符号上挂**属性**，用产生式关联属性的**语义规则**——这就是 SDD。
- **综合属性**（synthesized）：自下而上，由孩子算出父亲。本 lab 的物化：
  每个 `parse_*` 的返回值节点自带 `type` 字段（表达式类型）；
- **继承属性**（inherited）：自上而下，父亲传给孩子上下文。本 lab 的物化：
  `parse_stmt(loop_depth)` 的参数——"你在循环里吗"决定 break/continue 合法性。

5.2 节问"属性按什么顺序求"？对**L 属性 SDD**（继承属性只依赖左边的兄弟
和父亲）答案是：**一遍自左向右的深度优先就够**——这正是 5.5 节的实现方式，
也正是递归下降天然的执行顺序。理论在这里落地为一条工程规则：
**返回值 = 综合属性，函数参数 = 继承属性**。

### 2. 类型检查：翻译时顺手做（6.1 节预热）

规则的完整表在 [`src/parser.c`](src/parser.c) 的 `make_binop/coerce_assign`：

```
int op int → int        （/ 与 % 向零截断，C 语义）
任一 float → 插入 i2f，结果 float
% 含 float → 编译期错误（lab3 是运行期才撞上，lab5 提前了）
比较运算   → 提升两侧，结果 int 0/1
float←int  ：允许（宽度提升，包 i2f）
int←float  ：禁止（隐式收窄；Java/Rust/Swift 同此，C 允许是历史包袱）
```

两个工程细节：**i2f 显式进树**（后面阶段不用再查一遍类型）；
**TY_ERR 标记**（一处出错不再级联刷屏——错误恢复的通行做法）。

### 3. 作用域链：符号表的核心结构（2.7 节）

每个 `{}` 块一个 Scope（内含哈希表），`parent` 指针连成链；
`scope_push/pop` 对应进/出块，`sym_lookup` 沿链向外找、**第一层命中即胜出**——
这就是"内层声明遮蔽外层同名"。两个本 lab 特有的决定：

- **pop 不释放**：`-symtab` 要 dump 所有出现过的作用域（含已退出的块）；
- **A_VAR 节点直接挂 Sym\***：名字解析在编译期一次完成，运行期只比较指针
  ——不同作用域的同名变量是不同 Sym，天然不会查错。

另注意登记时机：本 lab **先解析初始化式、再登记符号**，所以 `int x = x + 1;`
里的 `x` 指外层的 x（无外层则报错）——与 C++/Java/Rust 一致；
C 的"声明点即刻可见"（`int x = x;` 是读垃圾值的 UB）是历史包袱。

### 4. 两趟：为什么"先检查、后执行"

lab3 边分析边执行，错了也执行一半；lab5 有了完整 AST，先检查全部通过，
再第二趟解释执行（[`src/eval.c`](src/eval.c)）。两趟之间就是将来 lab6
"生成三地址码"的位置——届时第三趟按 IR 执行，而 eval.c 一行不改，
正好当 lab6/lab7 的**参考实现对拍**。运行期环境用帧栈（进块压帧/出块弹帧），
结构上与编译期作用域链一一对应——这是 lab7 活动记录的直接前身。

## 练习

1. **加显式转换 `(int)e` / `(float)e`**：文法 `factor → ( int ) factor | ...`
   （词法器零改动，`int` 已是关键字），实现 `f2i` 节点——然后 `int x = (int)1.5;`
   应当合法。做完体会"禁止隐式收窄 + 提供显式转换"才是一套完整设计。
2. **把赋值做成表达式**（`x = y = 1;` 右结合）：在 `parse_expr` 最外层加
   `IDENT = expr` 候选，AST 加赋值表达式节点。对照 C 的"赋值是表达式"的代价
   （`if (x = 1)` 笔误从此可能）——这就是 C++ 后来引入 `if (x = y)` 显式警告、
   Go/Rust 干脆禁止赋值表达式出现在条件里的原因。
3. **加 `&&` `||` 与短路求值**：需要新的求值顺序（左操作数可能决定不再求右
   操作数）——对 AST 是两个新节点，对类型检查是多一层"要求两侧 int"。
4. **常量折叠**：在 `make_binop` 里对 `(int字面量 op int字面量)` 直接算出
   结果节点——5.1 节"在树上做翻译"的又一例，也是 lab9 优化的第一课。
5. **改登记时机**：把 `parse_decl` 改成"先登记后解析初始化式"，观察
   `int x = x + 1;` 从报错变成合法（语义变成 C 的 UB 形状）——理解 2.7 节
   "声明在哪里生效"是个语言设计决定。

## 龙书 vs 现代

- **AST 是现代编译器的中心数据结构**：Clang 的 `-Xclang -ast-dump` 输出
  与本 lab 的 S-表达式风格神似（本 lab 有意为之）；rustc 把 AST 降级为
  HIR 再到 MIR/IR，Go 从 AST 直达 SSA——"先物化成树，再在树上做翻译"
  已是完全统一的路线。
- **语法制导翻译的"属性文法"理论很少被直接引用**，但它的工程形态
  （返回值=综合属性、参数=继承属性、一遍深度优先）就是每一个手写前端
  的日常——理论的价值是让你**确信这样写没有漏掉什么**（L 属性保证
  一趟可解）。
- **名字解析成指针**：本 lab 的 A_VAR 挂 `Sym*`，对应 Clang 的 `DeclRefExpr`
  挂 `ValueDecl*`、rustc 的 `DefId`。运行期/后续阶段不做字符串比较，
  是性能与正确性（遮蔽）的双重要求。
- **类型系统在收紧**：本 lab 的 `int←float` 禁令与 Java/Rust/Swift 一致；
  C/C++ 保留隐式收窄（及悬空 else、赋值表达式）是因为要兼容 50 年前的
  代码。新语言还把"条件必须 bool"定为硬规则（本 lab 仍沿用 C 的
  "非零为真"，见 `parser.c` 的取舍注释）。
- **lab3 是解释器形状，lab5 起是编译器形状**：一趟边走边算 vs 多趟
  中间表示。下一站 lab6 在两趟之间生成三地址码——编译器的"腰"。
