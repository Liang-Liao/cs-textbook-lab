## 理论精要

### 1. 三种自动机的关系（3.6 节）

- **DFA**（确定）：每状态每字符恰有一条转移——快，但正则不好直接画成它；
- **NFA**（不确定）：同一字符可以有多条转移——正则很好画成它，但"执行"要猜；
- **ε-NFA**：额外允许"不消费字符就跳转"（ε 边）——Thompson 构造的产物。

三者的等价性转换链就是本 lab 的全部：**正则 → ε-NFA →（消 ε、消不确定）→ DFA →（合并等价状态）→ 最小 DFA**。

### 2. Thompson 构造（3.7.1）

对 AST 的每个节点套用固定片段（见 `nfa.c` 文件头注释的 ASCII 图），
只增加 O(1) 个状态。验证：`(a|b)*abb` 得到 14 状态 NFA——
与龙书图 3.34 完全一致（测试 2 自动检查）。

### 3. 子集构造（3.7.2，算法 3.20）

核心思想一句话：**DFA 的一个状态 = NFA 状态的一个子集**，
含义是"NFA 读完同一个串之后，可能处于的所有位置"。

```
开始: D0 = ε-closure({NFA 开始状态})
循环: 取未标记的子集 T
      对每个字符 c: U = ε-closure(move(T, c))
      若 U 是新的 → 加入 Dstates；Dtran[T,c] = U
```

`(a|b)*abb`：14 状态 NFA → 5 状态 DFA（其中一个不可达接受区分裂状态随后被合并）。

### 4. 最小化（3.9 节）

等价状态 = 接受标记相同 + 每个字符去往等价状态。做法是**划分细化**：
初始按"接受/不接受（及接受于哪条规则）"分组，反复用转移目标组分裂小组，
直到不动点。`(a|b)*abb` 的最小 DFA 恰好 4 个状态——龙书图 3.9 的经典结果。

> 教学版用 O(n²·|Σ|) 的朴素细化；工业级是 Hopcroft 的 O(n log n)。
> 另外注意：**接受于不同规则的状态不能合并**（tag 不同），否则 token 类别就乱了。

### 5. mini-flex：多规则并联 + 最长匹配（3.5 节）

flex 把所有模式**并联**成一个 NFA（`nfa_build_multi`），每条规则的接受状态
打上自己的 tag。扫描时两条语义（`scan.c` 实现的就是它们）：

1. **最长匹配优先**：`3.14` 同时匹配 `[0-9]+`（长 1）和 `[0-9]+\.[0-9]*`（长 4）
   → 取浮点数规则。这就是为什么规则文件里 FLOAT 写在 INT 前也无所谓。
2. **等长时先写的规则赢**：`if` 与关键字规则（长 2）和标识符规则（长 2）等长
   → 关键字规则写在前面所以赢。这就是"关键字规则必须放在标识符规则前"的原因。

对照 lab1：手写词法器用"先按标识符扫、再查关键字表"实现同样的效果——
**两种流派殊途同归**，这正是工程与理论的漂亮对偶。

### 6. 块注释的正则陷阱

`minic.rules` 里的块注释规则：

```
/\*([^*]|\*[^/])*\**\*/
```

`([^*]|\*[^/])` 表示"非星号字符，或星号后面跟的不是斜杠"——
处理 `/*a**/` 这种连续星号结尾。正则不容易写对注释这类"嵌套感"的模式
（真嵌套如 `/* /* */ */` 正则根本做不到，那是上下文无关文法的活儿，lab3 见）。

## 龙书 vs 现代

- **lex/flex 没有淘汰，但大型编译器回归手写**（与 lab1 相同的结论）：
  flex 仍在维护、GNU 工具链内部还在用；但 GCC/Clang/V8/TypeScript 的词法器
  都是手写的。自动生成 vs 手写之争的实质：**生成器赢在规范集中、手写赢在
  诊断质量与上下文处理**。
- **正则引擎的两大流派**（龙书未展开）：
  - 自动机派（本 lab / RE2 / Rust regex）：线性时间保证，不支持反向引用；
  - 回溯派（PCRE / Python re / Java）：功能全（捕获组、断言、反向引用），
    但最坏指数级——"灾难性回溯"(ReDoS) 的根源。
- **flex 实际不做 DFA 最小化**：直接用子集构造的结果 + 字符等价类压缩表
  （把 256 个字符按"转移行为相同"分组）。最小化是理论必学，工程取舍不同。
- 现代"从规则生成扫描器"的思想非常活跃：ANTLR、tree-sitter 的词法层、
  各种 IDE 高亮引擎都是"正则规则 → 自动机"的变体。
