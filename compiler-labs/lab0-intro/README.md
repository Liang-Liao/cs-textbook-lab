## 这个 lab 解决什么问题

龙书开篇把编译器画成流水线：

```
字符流 ──词法分析──> 记号流 ──语法分析──> 语法树 ──…──> 目标代码
```

第一次看到这张图很难有体感。本 lab 把它压缩成 200 行可运行的 C：
**输入中缀表达式（人写算术的习惯写法），输出后缀表达式（机器友好形式）**——
这本身就是一次完整的"编译"：源语言是中缀算术式，目标语言是后缀算术式。

```
输入:  3 + 4 * 2
输出:  3 4 2 * +
求值:  11
```

## 快速上手

```bash
cd lab0-intro
mingw32-make                       # 或 gcc -std=c11 -Wall -Wextra -O2 -o infix2postfix.exe src/infix2postfix.c
echo "3+4*2" | ./infix2postfix.exe           # 翻译
echo "3+4*2" | ./infix2postfix.exe -e        # 翻译并求值
echo "3+4*2" | ./infix2postfix.exe -v        # 显示每步翻译过程（强烈推荐！）
bash tests/run_tests.sh                      # 跑测试
```

`-v` 的输出长这样（请务必亲手跑一遍，逐行核对下面的规则表）：

```
  token=3      | 运算符栈=[]   | 输出=
  token='+'    | 运算符栈=[]   | 输出=3
  token=4      | 运算符栈=[+]  | 输出=3
  token='*'    | 运算符栈=[+]  | 输出=3 4
  token=2      | 运算符栈=[+*] | 输出=3 4
  token=END    | 运算符栈=[+*] | 输出=3 4 2
最终输出: 3 4 2 * +
```

## 理论精要

### 1. 后缀表达式（逆波兰式）

后缀式**不需要括号、不需要优先级**，用一条规则即可求值：

> 从左到右扫描；遇到数压栈；遇到运算符弹出两个数计算、结果压栈。

`3 4 2 * +` 的求值轨迹：压 3，压 4，压 2，遇 `*` 弹 4、2 得 8 压栈，遇 `+` 弹 8、3 得 11。
（这个"数栈机器"就是 lab7 栈式虚拟机的雏形，JVM 字节码本质上是后缀式指令流。）

### 2. 翻译规则（龙书 2.5 节思想的栈式等价物）

| 当前记号 | 动作 |
|---|---|
| 数字 | 直接输出 |
| 运算符 op | 弹出栈顶所有**优先级 ≥ op** 的运算符并输出，然后 op 入栈 |
| `(` | 入栈（屏障） |
| `)` | 弹栈输出直到弹出 `(`，`(` 丢弃 |
| 行结束 | 弹空运算符栈，依次输出 |

两个关键细节，都直接对应龙书后面章节的正式概念：

- **数字字面量**：交给 `strtod` 解析，因此除整数/小数外，科学计数法
  （`6.02e23`）也天然可用——这是"实现强于文法"的例子，练习时知道即可。
- **"≥ 也弹"实现左结合**：`10-3-2` 输出 `10 3 - 2 -` = `(10-3)-2` = 5。
  若误写成"＞ 才弹"就变成右结合 `10-(3-2)` = 9（练习 2 会故意利用这一点）。
- **优先级决定弹到哪**：`+` 遇到栈顶的 `*` 不会去弹它——这就是
  "乘法优先级高于加法"在翻译器里的实现方式。

## 练习（改代码验证你的理解）

1. **加幂运算 `^`**：优先级最高、**右结合**（`2^3^2 = 2^(3^2) = 512`）。
   提示：右结合意味着遇到同优先级的栈顶**不要弹**（`>` 而不是 `>=`）。
2. **加一元负号**：`-3 + 5` 与 `2 * -3`。提示：难点在于区分一元/二元 `-`
   （看前一个 token 是不是数字或 `)`），lab3 的文法会给出更优雅的答案。
3. **故意破坏左结合**：把普通运算符的比较改成 `>`，用 `-v` 观察
   `10-3-2` 的输出和求值结果变化。
4. 用 `-v` 逐行解释 `(7+3)/(2+3)` 的完整翻译过程（不看上文规则表）。

## 龙书 vs 现代

- **输入缓冲区对（龙书 3.2 节）已经过时**：那是磁带/小内存年代的技术
  （两个半区轮流装入 + 哨兵字符）。现代编译器直接把整个源文件读进内存。
  本 lab 用 `fgets` 逐行读，是同样的"现代"思路。
- 龙书 2.5 节用**语法分析器 + 语义动作**做这个翻译；我们先用运算符栈
  "绕过"了显式的文法——这是历史上真实出现过的技术路线
  （operator-precedence parsing，Floyd 1963，早期 Fortran 编译器用过）。
  lab3/lab4 会回到"显式文法"的正统路线，届时回头看本 lab，
  你会发现运算符栈其实就是一台"只会处理运算符优先文法的 LR 自动机"。
- 后缀式作为**教学 IR** 很好，现代编译器主流 IR 是 SSA 形式
  （见 [docs/MODERN-NOTES.md](../docs/MODERN-NOTES.md) 第 6 章条目）；
  但后缀思想活在 JVM/.NET 字节码、PostScript 和所有栈式求值里。
